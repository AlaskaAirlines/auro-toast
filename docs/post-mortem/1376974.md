# AB#1376974

## Executive Summary

[AB#1376974](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1376974)

The `auro-toast` component was updated to fire events using web-standard naming. It now dispatches a `toast-close` event — the correct, lowercase kebab-case form — alongside the older `onToastClose` event, which is now deprecated. The component was also corrected to properly map its camelCase JavaScript properties to lowercase HTML attributes, fixing a long-standing mismatch between how attributes were documented and how browsers actually expose them. The package now ships a machine-readable API manifest (`custom-elements.json`) that enables IDE autocomplete and design-system tooling to work correctly.

## The Problem

The toast component was firing its close event under the name `onToastClose` — a camelCase-with-`on`-prefix pattern borrowed from older frameworks. Web components are expected to use lowercase kebab-case event names (like `click`, `change`, `toast-close`) so that consumers can attach listeners with standard `addEventListener` calls and so that frameworks like Vue, React, and Svelte can bind to them without workarounds.

Additionally, the component's JavaScript properties (`disableAutoHide`, `noIcon`, `timeTilHide`) were being exposed to HTML as camelCase attribute names — but browsers silently lowercase all HTML attribute names. This meant `<auro-toast disableAutoHide>` would never actually set the property. The machine-readable API manifest (`custom-elements.json`) was missing entirely, and the `variant` property lacked an explicit list of its accepted values, preventing tooling from validating or suggesting correct options.

## Root Cause

In `src/auro-toast.js`, the `closeToast()` method dispatched only one `CustomEvent` named `"onToastClose"`. The three boolean/number properties (`noIcon`, `disableAutoHide`, `timeTilHide`) were declared in `static get properties()` without an `attribute` key — causing Lit to derive the attribute name directly from the property name, producing camelCase attribute names that the browser would lowercase on receipt. The class-level `@attr` JSDoc annotations documented the camelCase names too, so both the runtime and the documentation were wrong in the same way. The `package.json` had no `"customElements"` field, so even after generating `custom-elements.json` it would not be discoverable by tooling.

## The Fix

- **Added `toast-close` event dispatch** in `closeToast()` alongside the existing `onToastClose` dispatch, so both fire on every close — maintaining backwards compatibility while introducing the standards-compliant name.
- **Deprecated `onToastClose`** via `@deprecated` JSDoc and updated the class-level `@fires` declaration.
- **Added explicit `attribute` keys** to the three affected Lit property definitions in `static get properties()`, mapping each camelCase property to its correct lowercase HTML attribute name:
  - `noIcon` → `attribute: "noicon"`
  - `disableAutoHide` → `attribute: "disableautohide"`
  - `timeTilHide` → `attribute: "timetilhide"`
- **Added inline `/** @type */` JSDoc** above each property definition inside `static get properties()`, replacing the removed class-level `@attr` tags.
- **Corrected CEM event types** from bare `{object}` to `{{ visible: boolean }}` in the `closeToast()` JSDoc.
- **Changed `variant` type** from `{String}` to `{"error" | "success" | "custom"}` union.
- **Added `"customElements": "custom-elements.json"`** to `package.json`.
- **Generated `custom-elements.json`** with all corrected attribute names, types, and event shapes.
- **Updated `docs/api.md`** to the new auro-cli table format with correct lowercase attribute names, the new `toast-close` event, and the `register` method.

## Why This Works

The `attribute` key in Lit's `static get properties()` is the authoritative way to declare the HTML attribute name for a property. Setting it to the lowercase string ensures Lit's attribute-to-property reflection works correctly at runtime (not just in documentation), and the CEM analyzer picks it up as both the `name` in attributes and the `attribute` in members — keeping the `fieldName` as the camelCase JS property name. Dispatching both `onToastClose` and `toast-close` on every close means no existing consumer breaks. The `"customElements"` package field is the standard discovery mechanism for VS Code, web-types generators, and Catalyst.

## Outcome

The toast component now fires events with standards-compliant names, and its HTML attributes bind correctly in all browsers and frameworks. IDE autocomplete correctly suggests `variant` values and the lowercase attribute names. The design-system CEM validator passes with 0 errors and 0 warnings. The `onToastClose` event continues to fire for backwards compatibility during the deprecation window.

## Learnings

- **Use Lit's `attribute` key, not just JSDoc, to declare lowercase attribute names.** Setting `attribute: "myattr"` in `static get properties()` fixes the runtime binding and the CEM output simultaneously; relying on `@attr` JSDoc alone only fixes documentation.
- Web component custom events must use **lowercase kebab-case** names (`toast-close`, not `onToastClose`) to be compatible with standard `addEventListener`, Vue `v-on`, React synthetic events, and Svelte event directives.
- **Dispatch both old and new event names** during a deprecation period — this keeps existing consumers working and gives teams a migration window.
- The `"customElements"` field in `package.json` is required for VS Code, web-types, and Catalyst to auto-discover the component manifest; publishing `custom-elements.json` without this field means it is silently ignored.
- CEM type annotations should use **explicit shapes** (`{ visible: boolean }`) over bare primitives (`object`, `string`) — bare types generate no autocomplete and fail stricter linting rules.
- Inline `/** @type */` JSDoc inside `static get properties()` is the correct place to document Lit reactive properties in JavaScript (no TypeScript decorators); class-level `@attr` tags are redundant once `attribute:` is set.

## Iterations That Didn't Work

- **Class-level `@attr` tags with lowercase names.** The initial approach was to change `@attr {Boolean} disableAutoHide` to `@attr {Boolean} disableautohide` in the class-level JSDoc block. This updated the CEM documentation but did not fix Lit's runtime attribute binding — the browser would still receive the camelCase name. The correct fix is `attribute: "disableautohide"` in the property definition, which controls the Lit runtime and the CEM together.
- **Duplicate JSON keys during `custom-elements.json` editing.** When patching the `variant` type with a `replace_all` edit, the replacement pattern added a new `type` key without removing the existing one, producing invalid JSON with two `type` keys in the same object. The fix required reading the affected block and replacing the whole duplicate entry.
